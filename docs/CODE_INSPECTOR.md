# AL AI Code Inspector — دامنه و محدودیت‌ها

## هدف

Code Inspector یک تحلیل‌گر ایستای محلی است که فایل‌های متنیِ کد و پیکربندیِ قابل‌دسترسی را در جریان اسکن سریع و عمیق بررسی می‌کند. کد اجرا، کامپایل، نصب یا به سرور ارسال نمی‌شود و فایل اصلی تغییر نمی‌کند.

این قابلیت از موتور تشخیص بدافزار جداست. یک ایراد کدنویسی به‌تنهایی به معنی ویروسی بودن فایل یا برنامه نیست.

## قالب‌های شناخته‌شده

پسوندهای فعلی شامل Kotlin/Kotlin Script، Java، Python، JavaScript/TypeScript، C/C++، C#، Go، Rust، PHP، Ruby، Swift، Shell، PowerShell، SQL، HTML، CSS/SCSS، XML، JSON، YAML، TOML، Gradle و Properties هستند.

شناخت پسوند به معنی پشتیبانی از تحلیل کامل زبان نیست. عمق بررسی برای زبان‌ها یکسان نیست و نسخه فعلی یک تحلیل‌گر سبک مبتنی بر قواعد است، نه کامپایلر یا parser کامل هر زبان.

## بررسی‌های فعلی

- ساختار عمومی: پرانتز، کروشه و آکولاد نامتوازن؛ رشته و توضیح بسته‌نشده.
- Python: چند بررسی ابتدایی برای پایان دونقطه در بعضی دستورها.
- JSON: بررسی ساختار، رشته‌ها، اعداد، آرایه‌ها و اشیاء.
- XML: بررسی تطابق و بسته‌شدن تگ‌ها.
- الگوهای امنیتی: محتوای شبیه کلید خصوصی یا رمز ثابت، URL با HTTP، اجرای پویای کد، subprocess با shell=True، بارگذاری pickle، ساخت پرس‌وجوی SQL با الحاق رشته، بررسی ناامن TLS، الگوریتم‌های قدیمی مانند MD5/SHA-1/DES، sinkهای HTML، handler خالی و برخی موارد کیفیت کد.

گزارش هر یافته شناسه قاعده، شدت، شماره خط و ستون، توضیح فارسی/انگلیسی را نمایش می‌دهد.

## محدودیت‌های پردازش

- حداکثر اندازه متن برای تحلیل کد ۱ مگابایت است. فایل بزرگ‌تر در صورت امکان همچنان هش‌گذاری می‌شود، اما تحلیل کد آن با وضعیت «محدود» نمایش داده می‌شود.
- محدودیت عمومی موتور اسکن فایل و سقف‌های اسکن دستگاه همچنان اعمال می‌شوند.
- اسکن فقط فایل‌هایی را می‌بیند که Android به برنامه دسترسی می‌دهد.
- APK برنامه‌های نصب‌شده در این نسخه decompile یا disassemble نمی‌شوند؛ این قابلیت متن منبع داخل APK را استخراج نمی‌کند.
- این نسخه تحلیل وابستگی‌ها، CVE library inventory، interprocedural/data-flow analysis، تحلیل رفتاری، یا بررسی کامل خطاهای منطقی و زمان اجرا ندارد.
- برای Java/Kotlin/Python و سایر زبان‌ها، خطای کامپایل کامل تولید نمی‌شود؛ بررسی ساختاری و الگوهای محدود جایگزین کامپایلر نیست.

## تفسیر نتیجه

یافته‌های ایستا هشدار یا نشانه برای بازبینی هستند، نه اثبات قطعی آسیب‌پذیری. نبود یافته نیز صحت برنامه یا نبود همه آسیب‌پذیری‌ها را تضمین نمی‌کند. قواعد می‌توانند false positive و false negative داشته باشند؛ مخصوصاً وقتی الگو در متن یا نمونه آزمایشی آمده باشد.

نتیجه «تحلیل کد انجام شد» فقط یعنی قواعد فعال روی محتوای قابل‌خواندن اجرا شدند. برنامه هیچ کدی را خودکار اصلاح، حذف یا اجرا نمی‌کند. تغییرات باید توسط توسعه‌دهنده بررسی و اعمال شوند.

## توسعه بعدی برای کیفیت تولیدی

1. افزودن parserهای معتبر و نگه‌داری‌شده برای هر زبان با نسخه‌بندی و آزمون سازگاری.
2. اتصال بررسی‌های تخصصی زبان مانند Kotlin/Java compiler diagnostics، Python AST و ابزارهای SAST معتبر.
3. تحلیل جریان داده و مسیرهای منبع تا مقصد برای SQL injection، XSS، command injection و افشای اسرار.
4. بررسی وابستگی‌ها و تطبیق نسخه کتابخانه‌ها با پایگاه‌های CVE معتبر.
5. ساخت مجموعه آزمون benign/vulnerable برای اندازه‌گیری false positive و false negative.
6. نگه‌داشتن تمام پردازش محلی یا اخذ رضایت صریح و شفاف پیش از هر نوع ارسال نمونه یا هش به سرویس آنلاین.
